# Sphere Room 模块完工检查点

> 本文件是**随仓库版本化的正式副本**；Codex 实际加载的是个人目录 `~/.codex/skills/sphere-room-checkpoint/` 的同名 skill。
> 改动流程时先改本文件，再同步到个人副本，避免两份漂移。

项目根：`E:\Unity Projects\MyTestGame`（Unity 6000.3.14f1 + URP + FishNet 4，Windows x64）。
一个「节点」= `PROGRESS.md` 里的 M0–M10 里程碑。本 skill 把节点收尾固定成：**验收 → 合规 → 勾选 → 提交 → 汇报**。

## 何时使用

- 用户说：这个模块/节点做完了、验收一下、提交这个节点、更新进度文档、开检查点。
- Agent 判断某个节点已满足 `PROGRESS.md` 的「完成定义」时，**主动提醒**用户「可以用 `$sphere-room-checkpoint` 收尾 Mx」，得到确认后再执行。
- 节点内多处改动攒到可以交付时。

## 收尾流程

### 1. 读上下文（不凭记忆）
- `PROGRESS.md`：当前节点是哪个、工作项与完成定义是什么、现在是不是 `[~]`。
- `AGENTS.md` + `CODING_STANDARDS.md`：规范是强制的，本 skill 不复述规则，直接按文件逐条自查（重点 §6 命名、§7 注释、§8 维护性、§10 清单）。
- `git status` + `git log --oneline -n 10`：确认工作区里哪些改动属于本节点，哪些是别的。

### 2. 判定是否真的完工
- 逐条对照该节点的「完成定义」；`PROGRESS.md` 未覆盖的验收点以 `AGENTS.md` 任务表与 `DEVELOPMENT_PLAN.md` 测试矩阵为准。
- 需要人在 Unity 里操作才能确认的项（Play、双开、ParrelSync 克隆、真机 Steam）**必须列出来让用户确认**；用户没确认前不勾选。
- 有未完成项就不要勾选，直接报告还差什么。

### 3. 规范自查（提交前必过）
按 `CODING_STANDARDS.md` §10 清单自查，最容易漏的四项：
- 命名（§6）：布尔 `Is/Has/Can` 前缀、方法动词开头、网络数据结构 `Input/Data/State` 后缀、材质 `Mat_` 前缀、无 Manager 滥用 / 模糊词 / 数字后缀 / 拼音。
- 注释（§7）：类头写职责 + 网络语义；网络方法首行标执行侧与触发时机（`[服务器|客户端|仅 Owner|双端]` + `[Tick 驱动|事件驱动|一次性]`）；热路径方法标 `[热路径]`；临时方案写 `// TODO(Mx):`。
- 开闭原则（§8.1）：**不得为加功能修改已勾选节点的核心类**，改走新增类 / 新增组件 / 订阅已有事件；确实必须改时在提交信息里写明理由。
- 编译 0 error 0 warning；调参集中在 `PhysicsTuning`；无新增 static 单例（NetworkManager 除外）。
发现问题先修，再往下走。

### 4. 更新文档
- `PROGRESS.md`：节点改 `[x]`，并在节点末尾追加 `**完工**：<提交哈希>（<日期>）` 与必要的取舍说明；顺带更新第 0 节现状表（依赖 / 场景 / 工具变化）。
- 发现**包内 API 与文档描述不一致**时，改文档并在提交信息注明「以包内为准」。
- 其他 md 只在有真实新发现时更新；**仓库只记项目与业务内容**——环境排查、工具踩坑、临时试验过程不要写进仓库。
- 不为了让文档好看而记录没做过的事。

### 5. 提交

- **前置条件：用户明确要求提交**。本项目的协作约定是"默认不自动提交"——改动先留在工作区，用户说"提交 / git"时才执行本节；用户没说就不要 commit（哪怕节点已验收）。
- Conventional Commits + 中文描述；一个节点至少一个提交，节点内可按功能拆多个；**严禁 squash / 改写历史**。
- 只提交本节点相关文件；`Library/`、`Temp/`、`Logs/`、`Build/`、`UserSettings/` 已被忽略，不要 `-f` 强推。
- 提交信息写清：做了什么、与文档不一致的 API 决策、遗留取舍。

### 6. 汇报
四件事：勾选了哪个节点、提交哈希、还需用户确认的验收项、下一个节点（按 `PROGRESS.md` 顺序）。

## 边界

- 不勾选未验收的节点；用户没说"通过"就不算通过。
- 不把多个节点并进一个提交，也不在检查点里顺手做下一个节点的功能。
- 检查点只收尾不改需求；需求变更先改 `DEVELOPMENT_PLAN.md` / `AGENTS.md` 再实现。
