### 本轮核实过的 FishNet 4.7.3 事实（供后续复用，别再查）
- 包位置：`Library/PackageCache/com.firstgeargames.fishnet@382980e7eed4/`
- NetworkManager 属性：ServerManager / ClientManager / TimeManager / TransportManager / SceneManager / ObjectPool。
  PredictionManager 与 RollbackManager **不在 NetworkManager 上**，要走 `InstanceFinder.PredictionManager`。
- 生命周期回调（Runtime/Object/NetworkBehaviour/NetworkBehaviour.Callbacks.cs）：
  OnStartNetwork/OnStopNetwork、OnStartServer/OnStopServer、OnOwnershipServer(prev)、
  OnSpawnServer(conn)/OnDespawnServer(conn)、OnStartClient/OnStopClient、OnOwnershipClient(prev)。
- `[SyncVar]` 特性在 4.7 已标记 Obsolete，改用 `SyncVar<T>`（项目 PlayerIdentity 已如此）。
- `[Replicate]` 与 `[Reconcile]` 必须成对：ILPP 在 `PredictionProcessor.cs` 里校验，否则编译后报错（BallPrediction 的空 `Move(NoInput)` 就是为满足此契约）。
- TimeManager.PhysicsMode：Unity=0 / TimeManager=1 / Disabled=2。
- TickNetworkBehaviour（`Runtime/Utility/Template/`）在 `OnStartNetwork_Internal` 才订阅 TimeManager，所以
  `SetTickCallbacks` 必须写在 OnStartNetwork，不能写 Awake。
- 预测官方骨架：`Demos/Prediction/Rigidbody/Scripts/RigidbodyPrediction.cs`。

### 讲解中给出的关键判据（用户此前的痛点）
- Kinematic vs Dynamic 的正确问法不是"哪个更好"，而是"它要不要被物理推动 / 要不要本地零延迟 / 与静态世界的碰撞交给谁"。
- 选 Kinematic = 宣布墙的阻挡不再由 PhysX 负责（默认 Contact Pairs 无 kinematic-static 接触对），必须自 sweep。这属于 Unity 物理知识，不在 FishNet 文档里——用户混乱的根源之一。
- 联机三个独立学习面：通用模型 / FishNet 接口 / Unity 物理与时序，必须分开学。
